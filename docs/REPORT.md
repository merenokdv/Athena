## 1. Цель и бизнес-контекст

### 1.1. Подразделение / роль

**Персональный knowledge-assistant** (аналог knowledge-worker / внутренней техподдержки для одного специалиста):

- быстрый поиск по учебным и рабочим заметкам;
- ответы на вопросы «как я это делал раньше?»;
- меньше времени на ручной обход сотен файлов Obsidian;
- ответы **только** из базы, с указанием источника.

Соответствует заданию: корпус инструкций / FAQ / техдоков выбран слушателем самостоятельно.

### 1.2. Задачи ассистента

1. Найти релевантные фрагменты заметок по смыслу и по имени файла.  
2. Сжать ответ в понятные шаги.  
3. Показать источники (имя заметки).  
4. Отказать, если данных нет (антигаллюцинации).  
5. Демонстрировать тот же пайплайн, что и для корпоративного DSS отдела.

### 1.3. Почему имя Athena

Греческая богиня мудрости и разумного совета — метафора «умного начитанного помощника».  
Альтернативы, которые рассматривались: Metis (мудрый совет), Mnemosyne (память/заметки), Prometheus (знание людям).

## 3. Хронология работ: что сделано и как

Ниже — фактический путь сборки прототипа (удобно для слайда «как мы строили»).

### Этап A. Железо и окружение

| Компонент | Значение |
|-----------|----------|
| CPU | AMD Ryzen 7 3700X (8c/16t) |
| RAM | ~62 ГБ |
| GPU | NVIDIA RTX 3090 24 ГБ |
| Runtime LLM | Ollama 0.19 |
| Уже были модели | `qwen3.5:27b`, `qwen3.5:9b`, `qwen2.5-coder:14b`, … |

**Проблема:** сначала драйвер NVIDIA не был активен → Ollama на CPU → ответы очень медленные.  
**Решение:** установлен `nvidia-dkms-580-open`, GPU заработал (`nvidia-smi` видит 3090).

**Почему локально, а не Custom GPT:** персональные заметки, контроль данных, демо на своём железе.

### Этап B. Выбор архитектуры RAG

```
Заметки (ATHENA_KB)
    → ingest (chunk + embed)
    → Chroma (векторный индекс)
    → retrieve (поиск top-k)
    → Qwen (generate по контексту)
    → UI Athena
```

Почему RAG, а не «голый» чат: иначе нет привязки к корпоративной/личной БЗ и нельзя гарантировать источники.

### Этап C. Каркас проекта

```
rag-dss/
├── app/
│   ├── config.py       # модели, chunk, top-k, пути
│   ├── prompts.py      # system prompt / границы
│   ├── ingest.py       # индексация
│   ├── rag_chain.py    # гибридный retrieve + generate
│   ├── server.py       # FastAPI UI API
│   └── ui.py           # alias → server
├── web/                # кастомный UI
│   ├── index.html
│   └── static/{styles.css,app.js}
├── knowledge_base/     # демо-регламенты (корпоративный пример)
├── data/chroma/        # векторный индекс
├── docs/               # REPORT, ARCHITECTURE, TEST_LOG
├── scripts/            # ingest helpers, check_index, pdf_to_md, eval
└── requirements.txt
```

Стек: **Ollama · Chroma · LangChain · FastAPI · static HTML/CSS/JS**.

### Этап D. Ingest (индексация) — как это называется правильно

**Индексация / ingest** = превращение документов в searchable-представление:

1. **Load** — обход vault, отбор `.md`/`.txt`.  
2. **Chunk** — нарезка (~900 символов, overlap 150).  
3. **Embed** — векторы через `nomic-embed-text`.  
4. **Store** — Chroma, коллекция `personal_notes_kb`.

Команда:

```bash
PYTHONPATH=. python -m app.ingest
```

**История прогонов:**

| Версия | Что в индексе | Чанков | Комментарий |
|--------|---------------|--------|-------------|
| v1 | md + «сырые» PDF | ~2900 | шум от PDF в retrieval |
| v2 | только md/txt + имя файла в чанке | ~2439 | чище, PDF временно вне индекса |
| v3 | md/txt + PDF→MD | **3003** | актуальная |

**Текущая сверка (без чтения текста заметок):**

```text
файлов-кандидатов: 956
файлов в индексе:  956
чанков:            3003
покрытие:          100%
пустых пропущено:  4
```

Проверка покрытия:

```bash
PYTHONPATH=. python scripts/check_index.py
```

### Этап E. PDF → Markdown

Прямая индексация PDF давала шум. Решение: конвертация в `.md`:

```bash
PYTHONPATH=. python scripts/pdf_to_md.py
# → `<KB>/_pdf_converted`/*.md  (5 PDF)
```

В vault также есть `.docx`/`.odt` (пока не конвертировались; при необходимости — следующий шаг).

### Этап F. Retrieve + Generate

**Retrieve (сейчас гибридный):**
1. semantic search (векторы);  
2. доп. поиск по ключевым словам вопроса;  
3. буст чанков, у которых **имя файла** совпадает с темой (стемминг RU: фильм/фильмы/фильмов);  
4. top-k = 4 лучших фрагмента в промпт.

**Generate:**
- system prompt: только по контексту, отказ если пусто, указать источники;
- `temperature=0.2`, `num_ctx=4096`;
- `reasoning/think=False` (у Qwen3 иначе «думает» минутами даже на «привет»);
- приветствия обрабатываются без RAG (мгновенно).

### Этап G. Модель: 27B ↔ 9B

| Модель | Зачем |
|--------|-------|
| `qwen3.5:27b` | качество ответов (текущий режим демо) |
| `qwen3.5:9b` | быстрый интерактив, меньше VRAM |
| `nomic-embed-text` | embeddings для поиска |

Наблюдение: без отключения thinking и при холодной загрузке 27B первый ответ мог занимать >1 мин.  
После GPU + `think=false` + keep-alive — интерактив приемлемый.

Переключение в `app/config.py`: `LLM_MODEL = "qwen3.5:27b"` или `"qwen3.5:9b"`.

### Этап H. UI Athena (кастомный)

Gradio заменён на свой UI в минималистичном product-стиле (воздух, светлая палитра, крупный бренд на пустом экране; ориентир — эстетика работ вроде [Gleb Kuznetsov / Dribbble](https://dribbble.com/search/gleb-kuznetsov)):

- `GET /` — интерфейс  
- `GET /api/health` — модель / статус  
- `POST /api/ask` — `{question}` → `{answer, sources, model}`

Запуск:

```bash
bash scripts/run_ui.sh
# http://127.0.0.1:7860
```

### Этап I. Что делать при обновлении базы знаний

Индекс **не обновляется сам**. После добавления/правки/удаления заметок:

```bash
cd Athena
source .venv/bin/activate
PYTHONPATH=. python -m app.ingest           # пересобрать индекс
PYTHONPATH=. python scripts/check_index.py  # убедиться, что покрытие ок
# UI можно не трогать — читает индекс с диска; при смене модели — перезапуск
```

Если добавляете новые PDF:

```bash
PYTHONPATH=. python scripts/pdf_to_md.py
PYTHONPATH=. python -m app.ingest
```

## 5. Оценка качества и доработки (цикл улучшения)

### 5.1. Проблема v1 — шум PDF

Semantic search иногда поднимал нерелевантные PDF вместо нужных md.  
**Оценка retrieval:** часть запросов ~2–3/5.

### 5.2. Доработка v2 — чистый markdown + имя файла в чанке

- PDF убраны из прямого индекса;  
- в чанк добавлен префикс `Заметка: <путь>`;  
- переиндексация.

### 5.3. Доработка v3 — PDF→MD + гибридный поиск

**Симптом:** по бытовым запросам модель иногда говорила «в базе нет информации», хотя заметки с нужным словом в **имени файла** уже были в индексе.  
**Причина:** чистый semantic search плохо цеплял короткие формулировки к именам файлов.  
**Решение:** гибридный retrieve (векторы + буст по имени файла со стеммингом).  
**Проверка (только имена файлов, без чтения текста):** тематические запросы стали возвращать релевантные заметки по названию.

### 5.4. Шкала 1–5

| Балл | Смысл |
|------|-------|
| 5 | Верно, полно, источники, без выдумок |
| 4 | В целом верно, мелкие пробелы |
| 3 | Частично / шум |
| 2 | Слабо релевантно |
| 1 | Ошибка / галлюцинация / ложный отказ |

## 6. Экономическая эффективность

Учебно-демонстрационный расчёт (ставку можно заменить своей).

### 6.1. Затраты

| Статья | Оценка | Комментарий |
|--------|--------|-------------|
| Разработка прототипа | 12–20 ч | RAG, UI, доработки поиска, отчёт |
| Поддержка / мес | 2–4 ч | ingest, промпт, новые заметки |
| Лицензии | 0 ₽ | Ollama, Chroma, Qwen, FastAPI — локально |
| Инфраструктура | ПК с 3090 | облако не нужно |
| Энергия GPU | ~500–1500 ₽/мес | при активном использовании |

Пример: 16 ч × 1500 ₽ = **24 000 ₽** разово.

### 6.2. Эффект

- ручной поиск: 10–15 мин/вопрос;  
- с Athena: 1–3 мин;  
- 10 вопросов/неделя → ~8 ч/мес экономии → ~**12 000 ₽/мес** при ставке 1500 ₽/ч.

### 6.3. Окупаемость

≈ 24 000 / 12 000 ≈ **2 месяца** (персональный сценарий).  
В корпоративном пилоте (отдел, поиск регламентов) эффект масштабируется.

## 7. Пилот и риски

### 7.1. Пилот

1. Неделя 1 — 1–2 пользователя, лог 20 реальных вопросов.  
2. Неделя 2 — доработка корпуса/промпта, feedback «полезно/нет».  
3. Неделя 3 — сравнение времени «до/после».  
4. Успех: ≥70% ответов ≥4, корректные отказы, нет критичных галлюцинаций.

### 7.2. Риски

| Риск | Минимизация |
|------|-------------|
| Неполная БЗ | регулярный ingest + `check_index.py` |
| Шумный retrieval | hybrid search, фильтрация типов, PDF→MD |
| Галлюцинации | system prompt, только контекст, источники в UI |
| Медленные ответы | GPU, `think=false`, опция 9B |
| Сопротивление пользователей | демо пользы; помощник, не замена эксперта |
| Утечка данных | всё локально; не включать public share |
| Устаревший индекс | регламент: ingest после обновления vault |
